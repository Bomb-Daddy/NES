# EXEC0173 — source-executed RNG transfer telemetry (partial)

Preserves complete integrated EXEC0172 native 1280×720 C11 app. `gk173_rng_control.c/h` records **completed control transfers** from its existing original ROM-authenticated bounded 6502 CPU interpreter, rather than treating 986 raw `JSR $EF85` opcode-like byte patterns as executed instructions. The new `Gk83Trace.executed_rng_transfers` field counts distinct completed `JSR $EF85`, `JSR $C289`, fixed `$C1B8 JMP $C289`, other direct `JMP $C289` and indirect `JMP $C289` transfers, with bounded first/last evidence. The helper enforces input validation, overflow refusal, and no state mutation on rejection. `--source-executed-rng PRIVATE_ROM` exposes source-bounded counts from the actual compiled native game without exposing ROM bytes.

**Grounded source test:** exact owner-private NES ROM SHA256 `ada7066d9e71a81310fff78bc7037126798018a69dc2b92382c3cbdcd9b243b3`. There are **zero executed RNG/dispatcher transfers before that gate**. This does **not** show that Spring uses no RNG; the remaining setup path cannot be inferred until authentic PPU/mapper and initialized RAM state reproduce original runtime.
