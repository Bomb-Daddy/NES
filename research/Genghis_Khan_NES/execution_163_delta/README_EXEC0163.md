# EXEC0163 — source-authentic original Mesen savestate extraction (inherited complete C11 native app)

`gk163_mesen_import.c/.h` implements an actual bounded reader for original Mesen1 `.mss` save-state containers. It reads, but never decodes/exports, the screenshot section, validates the compressed serialized state, delegates RAM-bank proof to the existing independent Mesen parser, and extracts the 83-byte country records from authentic `mapper.saveRam` physical offset 0x0DCD, never fake empty `mapper.workRam`. Original archived Mongol 1175 has 14 records; World 1206 has 27. It authenticates against prior independent original-stock SHA-256 profiles and refuses malformed, mismatched, tampered, synthetic, WorkRAM or fresh-profile inputs atomically.

The existing native executable now exposes `--extract-original-mss <private-original-Mesen.mss> <mongol|world> <private-exclusive-destination.raw83>`. The written file may then be used as the already accepted `GK1_STOCK_SPRING_RECORDS` private input for the original checkpoint controller continuation. Output creation is exclusive; no overwrite. POSIX file creation permissions are private (umask 0077). Zlib is optional at build time, with explicit fail-closed `UNAVAILABLE` if absent (do not claim Windows installer parity).

**This is an actual source-processing and player-checkpoint preparation feature, NOT an original ROM first-Spring generator.** It does not invent the original 3 executable commands or merchant/AI/character RNG; untouched PRE_SETUP worlds are preserved. Reconstructed raw records, screenshot, private ROM and licensed data must NEVER be added to public GitHub. Native Mesen runtime was NOT rerun, and physical Xbox/Win32/NSIS/full campaign remain NOT RUN.
