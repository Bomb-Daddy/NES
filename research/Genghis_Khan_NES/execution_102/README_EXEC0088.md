# EXEC0088 — Source-projection integrity guard (0.88.0-dev1)

Same existing native C11 research game, inherited from complete EXEC0087. New `Gk79Checkpoint.source_verified` is set only following `gk77_load` against the three original Mesen source SHA-256 profiles. A verified source now requires the immutable, profile-pinned original 83-byte SHA identity as well as *both* original 83-byte record SHA integrity and complete equality of every port numeric field projected from those original records. All 14/27 countries are checked, including units, goods at +0x22, people, food, gold, economy, morale, and derived populations. In-place corruption of the mutable native country projection is denied even if the raw original record array remains untouched. A rewritten record plus recomputed unkeyed digest also fails: the SHA must still match one of the three fixed original-stock profile hashes, and the projected numeric values must agree. The check applies to `Pass`, controller command access and source-bound save/load, and protects against inadvertent divergence while the only source checkpoint operation is Pass. Other future legitimate actions will require a new source-versus-live-state model instead of incorrectly treating these captured values as permanently immutable.

The synthetic `gk79_from_decoded` fixture API keeps `source_verified=0`, preserving previously documented research fixtures and preventing them from being mislabeled original SHA-authenticated runs. This is NOT implementation of original NES setup, RNG, seasons, the 12 locked strategic commands, merchant offers, AI, or full campaign. No private original ROM or raw country records are bundled.

`test_gk88_source_projection` checks both scenarios, original projection, a variety of mutations and forged raw digest, save and Pass refusal without order change, and valid Pass. Original Mesen emulator not rerun; native Windows and physical controller not tested. Source-static is not runtime ROM parity.
