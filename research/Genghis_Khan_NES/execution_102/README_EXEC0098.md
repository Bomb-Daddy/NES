# EXEC0098 — source-bounded NES controller-$4016 research

This increment preserves the complete, separate EXEC0097 C11 native 1280x720 app and all prior generations. Version 0.98.0-dev1. A new NES port-1 serial-pad unit (`gk98_controller_port.c/.h`) supports strobe-high A-bit reads, falling-edge latch, A/B/Select/Start/directions serial low-order shifts and post-eight pull-up. **Upper CPU bus read bits are not known**: source-run callers explicitly supply a hypothetical mask. All default/older source-trace operations still stop at unmodeled IO.

`gk98_trace_reset_controller_hypothesis` accepts authenticated owner-private original-ROM bytes, explicitly hypothetical $2002 return sequence, a synthetic one-shot $C460 NMI and explicitly provided controller mask/bus-high bits. It traces further original source without pretending to reproduce actual CPU cycles, PPU interrupts, menu navigation, random stats or an original Mesen gameplay run. Invalid inputs and tampered original source return failure without modifying the caller output.

The native controller START source inspection uses the new trace and labels the **HYP** controller input and no playable Spring. No paid/proprietary ROM, RAM state, audio, image assets or saved game included in public source or package. Run `ctest -R GK1_098` alone or with `GK1_ORIGINAL_STOCK_ROM` owner-private path; full CTest inherits all existing tests. Windows executable/installer and a physical Xbox controller are NOT RUN.

The live original-ROM counterfactual trace has now advanced from the earlier source gate `$C6AE` / first `$4016` read to eight reads from each `$4016`/`$4017` controller, four shared `$4016` strobe writes, and a repeated source wait at `$C486` for an additional NMI/flag update. The deliberately limited trace reaches its instruction budget rather than claiming to complete that next interrupt. This experiment uses no actual Mesen controller or interrupt timing and must not be hardcoded as the game's normal first-Spring behavior. Additional instruction semantics exercised include ROR absolute,X, EOR absolute, LDY absolute,X. The 6502 ROR helper is exhaustively tested across all 512 byte/carry inputs.
